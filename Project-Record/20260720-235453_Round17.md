## 完成内容

### 1. BigInt 支持

**引擎层 (`src/engine/lr_engine.h`、`src/engine/lr_engine.c`)**
- 新增 `LR_TYPE_BIGINT` 值类型（tag=8，在 `LR_TYPE_SYMBOL` 之后）
- 新增 `LRBigInt` 结构体（引用计数 + 十进制字符串表示）
- 实现 `lr_new_bigint()`、`lr_is_bigint()` 函数
- BigInt 值的引用计数管理（`lr_dup_value`/`lr_free_value`）
- BigInt 类型转换支持（`lr_to_string`、`lr_equal`、`lr_strict_equal`）

**词法分析器 (`src/engine/lr_lexer.h`、`src/engine/lr_lexer.c`)**
- 新增 `TOK_BIGINT` 令牌类型
- 支持 `n` 后缀识别（如 `42n`、`0xFFn`、`1_000n`）

**语法分析器 (`src/engine/lr_parser.c`)**
- `TOK_BIGINT` 解析为 AST 字面量节点
- BigInt 字符串值存储在 `u.string.str` 中

**解释器 (`src/engine/lr_interp.c`)**
- 字面量求值：`eval_literal` 处理 `TOK_BIGINT`
- 类型检测：`typeof 42n` → `"bigint"`
- 二元运算：BigInt 与数字的 `+`、`-`、`*`、`/`、`%` 运算（转换为 float64 后计算）

**内置对象 (`src/lr_builtins_extra.c`)**
- `BigInt()` 构造函数（支持数字和字符串转换）
- `BigInt.prototype.toString()` - 转换为十进制字符串
- `BigInt.prototype.valueOf()` - 返回 BigInt 值
- `BigInt.asIntN(width, bigint)` - 截断为有符号整数
- `BigInt.asUintN(width, bigint)` - 截断为无符号整数
- 注册到全局对象

### 2. 函数调用展开语法 (`src/engine/lr_interp.c`)

**`eval_call` 函数**
- 支持 `AST_SPREAD_ELEMENT` 参数展开
- 使用动态数组（`total_argc` + `argv_cap` + `realloc`）处理可变参数
- 遇到 `...expr` 时评估表达式，如果是数组则展开其元素
- 更新 `argc` 为实际参数总数

**`eval_new` 函数**
- 与 `eval_call` 相同的展开逻辑
- 支持 `new Func(...args)` 语法

### 3. 可选链短路求值 (`src/engine/lr_interp.c`)

**`eval_call` 函数**
- 在评估 callee 后检查 `node->type == AST_OPTIONAL_CALL`
- 如果 callee 是 `null` 或 `undefined`，释放所有资源并返回 `LR_VALUE_UNDEFINED`
- 避免不必要的参数求值（短路优化）

### 4. for...in 堆损坏修复 (`src/engine/lr_engine.c`)

**`lr_get_own_property_names` 函数**
- 现在遍历 shape 链（`LRShape`）以枚举所有形状属性
- 从根 shape 开始遍历每个 slot 的 `prop_name` 和 `slot_index`
- 检查形状属性是否已在 `prop_hash` 中，避免重复枚举
- 不在 `prop_hash` 中的形状属性以默认 flags 添加到枚举结果中

**`lr_get_own_property_names_direct` 函数**
- 同样的修复逻辑

### 5. 测试更新

**`tests/test_engine.c`**
- 新增 6 个 BigInt 测试：
  - `test_bigint_typeof()` - `typeof BigInt === 'function'`
  - `test_bigint_new()` - `BigInt(42) === 42n`
  - `test_bigint_to_string()` - `BigInt(42).toString() === '42'`
  - `test_bigint_value_of()` - `BigInt(42).valueOf() === 42n`
  - `test_bigint_as_int_n()` - `typeof BigInt.asIntN === 'function'`
  - `test_bigint_as_uint_n()` - `typeof BigInt.asUintN === 'function'`
- 修复 `test_for_in_object()` - 现在实际测试 `for...in` 而不是跳过
- 总测试数：123（从 117 增加到 123）

## 已知问题
- `for...in` 在对象字面量上下文（`{a:1, b:2}` 被解析为 block）中仍有限制
- BigInt 算术运算使用 float64 转换，不完全支持任意精度（将在后续优化）
- 可选链 `eval_member` 的 `is_optional` 标志已在 `AST_OPTIONAL_MEMBER` 节点中处理
- 空值合并 `??` 已在 `eval_binary` 中处理
