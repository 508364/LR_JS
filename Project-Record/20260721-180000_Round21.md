## 完成的功能

### 1. GC 清除阶段 (sweep phase)

**文件**: `src/engine/lr_engine.c`

- 启用完整的 GC sweep phase：遍历 `obj_list`，释放所有 `gc_mark == 0` 且 `ref_count > 0` 的未标记对象
- **根对象保护机制**: sweep 前增加根对象（`global_obj`、`global_var_obj`、原型等）的 `ref_count`，防止在 sweep 过程中意外释放；sweep 后恢复引用计数
- 在 sweep 释放前将 `obj->props = NULL`、`obj->prop_count = 0`、`obj->proto = LR_VALUE_UNDEFINED`，防止级联释放导致链表遍历失效

### 2. 字节码序列化/反序列化

**文件**: `src/engine/lr_engine.c`

- 实现 `lr_read_object` / `lr_write_object` 完整替换桩函数
- 支持二进制标记+数据格式，小端序
- 数据类型标记: `UNDEFINED(0)` / `NULL(1)` / `FALSE(2)` / `TRUE(3)` / `INT32(4)` / `FLOAT64(5)` / `STRING(6)` / `OBJECT(7)` / `ARRAY(8)` / `REFERENCE(9)`
- 使用 `ObjTracker` / `ReadTracker` 处理循环引用（通过对象地址跟踪）
- 字符串使用龙氏长度编码（LEB128-like variable-length encoding）

### 3. Array 系列完整 API

**文件**: `src/lr_builtins_extra.c`

- **TypedArray**: 10 种类型全部注册（Uint8/Int8/Uint8Clamped/Int16/Uint16/Int32/Uint32/Float32/Float64/BigUint64/BigInt64）
- **TypedArray 原型方法**: subarray, set, slice, fill, map, filter, reduce, sort, reverse, at, every, some, find, findIndex, forEach, includes, indexOf, join, lastIndexOf, copyWithin, entries, keys, values, toString, toLocaleString
- **DataView**: 构造函数 + getInt8/getUint8/getInt16/getUint16/getInt32/getUint32/getFloat32/getFloat64 + set 方法
- 对象类型: `LR_OBJ_TYPED_ARRAY (12)`、`LR_OBJ_DATA_VIEW (13)`
- 通过 `opaque` 数据存储 `TypedArrayData` / `DataViewData` 结构体

## 修复的关键 Bug

### Bug 1: TypedArray 注册时 prototype 被提前释放 (use-after-free) — 引起间歇性 SIGSEGV

**文件**: `src/lr_builtins_extra.c:3387-3396`

**根因**: 在 TypedArray 构造函数注册循环中：
```c
JS_SetPropertyStr(ctx, ctor, "prototype", proto);  // 存储 proto 但不 dup
JS_FreeValue(ctx, proto);  // !!! 释放 proto，但 ctor 仍引用它
```
`JS_SetPropertyStr` 不会 dup 值，而是直接存储传入的引用。`JS_FreeValue(ctx, proto)` 将 ref_count 减到 0，释放了 proto 对象。此后 `ctor.prototype` 指向已释放内存。后续通过 `lr_call_constructor` 创建 TypedArray 实例时，引擎需要访问 `ctor.prototype` 来设置原型链，导致崩溃。

**影响**: 约 30% 概率的间歇性 SIGSEGV 崩溃，尤其是在 `slice` / `subarray` 等创建新 TypedArray 对象的方法调用时。`malloc_consolidate(): unaligned fastbin chunk detected` — glibc 堆内存损坏检测。

**修复**: 使用 `JS_DupValue(ctx, proto)` 在 `JS_SetPropertyStr` 前增加引用计数：
```c
JS_SetPropertyStr(ctx, ctor, "prototype", JS_DupValue(ctx, proto));
```
DataView 注册处同样修复。

### Bug 2: lr_object_free 不处理 TypedArray/ArrayBuffer/DataView 类型（内存泄漏）

**文件**: `src/engine/lr_engine.c:232-270`

**根因**: `lr_object_free` 只处理了 `LR_OBJ_CFUNCTION`、`LR_OBJ_ARRAY`、`LR_OBJ_PROXY` 三种类型的 `extra` 数据释放。`LR_OBJ_ARRAY_BUFFER` 的 buffer 数据（`extra`）、`LR_OBJ_TYPED_ARRAY` 的 `TypedArrayData`（`opaque`）、`LR_OBJ_DATA_VIEW` 的 `DataViewData`（`opaque`）从未被释放，导致内存泄漏。

**修复**: 在 `lr_object_free` 中添加三种类型的清理代码：
- `LR_OBJ_ARRAY_BUFFER`: 通过 `ArrayBufferMeta` 中的 `free_func` 释放 buffer 数据
- `LR_OBJ_TYPED_ARRAY`: 释放 `TypedArrayData`（含 buffer 引用、名称字符串）
- `LR_OBJ_DATA_VIEW`: 释放 `DataViewData`（含 buffer 引用）

### Bug 3: lr_new_array_buffer 忽略 free_func 参数（内存泄漏）

**文件**: `src/engine/lr_engine.c:2904-2923`

**根因**: `lr_new_array_buffer` 接收 `free_func` 参数但直接声明 `(void)free_func;` 忽略它。buffer 数据在对象释放时永远无法被正确释放。

**修复**: 创建 `ArrayBufferMeta` 结构体，存储 `free_func` 和 `opaque`，保存在 `obj->opaque` 中。在 `lr_object_free` 中通过 `meta->free_func(meta->opaque, obj->extra)` 正确释放 buffer 数据。

### Bug 4: GC mark 不标记 TypedArray 的 buffer 引用

**文件**: `src/engine/lr_engine.c:2551-2630`

**根因**: GC 标记阶段没有处理 `LR_OBJ_TYPED_ARRAY` 和 `LR_OBJ_DATA_VIEW` 类型，导致 TypedArray 引用的 ArrayBuffer 在 GC 标记-清除过程中被错误地当作垃圾回收。

**修复**: 在 `lr_gc_mark_object` 的 switch 语句中添加两个 case：
- `LR_OBJ_TYPED_ARRAY`: 标记 `tad->buffer`
- `LR_OBJ_DATA_VIEW`: 标记 `dvd->buffer`

### Bug 5: typed_array_create 使用 Object.prototype 而非 TypedArray.prototype

**文件**: `src/lr_builtins_extra.c:2045-2070`

**根因**: `typed_array_create` 在创建新对象时使用 `JS_NewObject(ctx)`，该函数创建的对象以 `Object.prototype` 为原型。当 `slice` / `subarray` 等方法内部调用时，新创建的 TypedArray 对象原型链不正确。

**修复**: 在创建对象后，通过 `tad->name` 从全局对象查找对应的构造函数，获取其 `prototype` 属性，用 `JS_SetPrototype` 设置正确的原型链。
