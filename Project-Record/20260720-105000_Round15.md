# Round 15 - Map/Set/Proxy/Reflect + 错误堆栈跟踪 + 性能优化

**时间**: 2026-07-20 10:50

## 目标
1. 实现 Map/Set 内置对象（C 哈希表实现）
2. 实现 Proxy/Reflect 内置对象（7 个核心 trap）
3. 增强错误堆栈跟踪（V8 兼容格式）
4. 引擎性能优化（AST 节点池、字符串驻留、直接线程化、内联缓存、形状缓存）
5. 修复所有编译问题和测试
6. 更新文档

## 完成内容

### 1. Map/Set 内置对象 (`src/lr_map.h/c`、`src/lr_set.h/c`)
- **Map**: 构造函数 (`new Map()`)、`set/get/has/delete/clear/size/forEach`
- **Set**: 构造函数 (`new Set()`)、`add/has/delete/clear/size/forEach`
- **底层实现**: C 哈希表（djb2 hash），支持任意类型键值，使用 `lr_set_opaque`/`lr_get_opaque` 附加数据
- **注册**: 在 `lr_register_builtins()` 中注册

### 2. Proxy/Reflect 内置对象 (`src/lr_proxy.h/c`、`src/lr_reflect.h/c`)
- **Proxy**: 构造函数 (`new Proxy(target, handler)`)、`Proxy.revocable()`
- **支持的 trap**: `get`、`set`、`has`、`deleteProperty`、`ownKeys`、`apply`、`construct`
- **Reflect**: 11 个静态方法
- **引擎集成**: 修改 `lr_engine.c` 中的属性访问函数检查 Proxy 类型
- **直通函数**: 添加 `lr_*_direct` 函数用于绕过 Proxy trap 的内部操作

### 3. 错误堆栈跟踪 (`src/engine/lr_engine.c`)
- **调用栈跟踪**: 解释器在函数调用时自动推入/弹出调用栈帧
- **`lr_capture_stack_trace`**: 捕获当前堆栈，返回 V8 格式字符串数组
- **`Error.prototype.stack`**: 惰性 getter，访问时才构建堆栈字符串
- **`Error.captureStackTrace(target)`**: V8 兼容的堆栈捕获 API
- **`Error.stackTraceLimit`**: 控制堆栈帧数上限（默认 10）
- **堆栈格式**: `at functionName (filename:line)` / `at filename:line`
- **Bug 修复**: 修复 `lr_register_error_builtins` 中的 use-after-free bug（`JS_SetPropertyStr` 后不应 `JS_FreeValue`）

### 4. 引擎性能优化
- **AST 节点池**: 解析器预分配 4096 个 AST 节点，减少 `malloc` 调用
- **字符串驻留**: 256 槽哈希表对标识符和字符串字面量进行原子化
- **内联常量**: 全局缓存节点（0、1、true、false、null、undefined）
- **直接线程化**: 解释器使用函数指针表替代 `switch` 语句
- **内联缓存**: 64 槽属性访问缓存
- **整数快速路径**: 二元运算的 int32 快速路径（14 种运算）
- **形状缓存**: 128 槽形状缓存，加速属性访问
- **小字符串缓存**: 128 槽缓存长度 <= 32 的字符串
- **GC 调优**: 调整 GC 阈值和新生代大小

### 5. 测试结果
- **85/85 全部通过，0 失败**
- 新增测试（10 个）：Map (2)、Set (2)、Proxy (2)、Reflect (2)、Error.stack (2)
- 修复了线程池 worker 线程的栈大小 (256KB -> 1MB) 和 use-after-free bug

## Key Bug 修复
1. **use-after-free in `lr_register_error_builtins`**: `JS_SetPropertyStr` 后不应调用 `JS_FreeValue`，因为 `lr_set_property` 已取得所有权
2. **Worker 线程栈溢出**: 从 256KB 增加到 1MB，避免复杂初始化时的栈溢出
3. **`lr_object_free`: 形状指针非 NULL 但未初始化**: 根本原因是对象被提前释放后内存被重用
