# Round 11 - MSVC 编译支持 + 多库输出

**时间**: 2026-07-19 08:56
**主题**: 完全支持 MSVC (cl.exe) 编译，构建系统输出静态库 + 动态库 + 可执行文件

---

## 目标
1. 完全支持 MSVC 编译器编译（Windows 开发标准工具链）
2. 构建多个库输出到编译目录（静态库 + 动态库/DLL + 可执行文件）
3. 保持 Linux/macOS GCC/Clang 兼容

## 完成内容

### 1. 新建 `src/lr_pthread_win.h` — MSVC pthread 兼容层 (~294 行)
- 仅在 `_MSC_VER` 定义时生效
- 使用 Windows 原生 API 模拟 pthread：
  - **Mutex**: `CRITICAL_SECTION` 封装为 `pthread_mutex_t`，支持 `PTHREAD_MUTEX_INITIALIZER`
  - **Condition Variable**: `CONDITION_VARIABLE` (Vista+) 封装为 `pthread_cond_t`
  - **Thread**: `_beginthreadex` 封装为 `pthread_create`/`pthread_join`
  - **Once**: `INIT_ONCE` 封装为 `pthread_once_t`
  - **TLS**: `TlsAlloc`/`TlsGetValue`/`TlsSetValue` 封装为 `pthread_key_*`
- 提供缺失的 POSIX 函数：
  - `gettimeofday()` — 使用 `_ftime_s()`
  - `usleep()` — 使用 `Sleep()`
  - `struct timeval` — 定义在 MSVC 下
  - `ssize_t` — 定义在 MSVC 下
  - `R_OK`/`W_OK`/`F_OK` — access() 常量

### 2. 更新 `src/lr_platform.h` — MSVC 编译器检测
- 新增 `LR_COMPILER_MSVC` 宏（`_MSC_VER` 检测）
- MSVC 编译时禁用常见警告（4996, 4244, 4267）
- Windows 下 pthread 根据编译器选择：
  - MSVC → `#include "lr_pthread_win.h"`
  - MinGW → `#include <pthread.h>`

### 3. 更新 `include/lr_js.h` — DLL 导出/导入宏
- 新增 `LR_API` 宏：
  - MSVC 构建 DLL 时：`__declspec(dllexport)`
  - MSVC 使用 DLL 时：`__declspec(dllimport)`
  - 静态库：空
  - Unix：`__attribute__((visibility("default")))`
- 所有 22 个公共 API 函数添加 `LR_API` 声明

### 4. 新建 `CMakeLists.txt` — 跨平台 CMake 构建系统
- 支持 MSVC (cl.exe)、GCC、Clang
- C11 标准（MSVC 用 `/std:c11`）
- 多目标输出：

| 目标 | 类型 | Windows 输出 | Linux/macOS 输出 |
|------|------|-------------|-----------------|
| `lr_engine` | 内部静态库 | `lr_engine.lib` | `liblr_engine.a` |
| `lr_js_core` | 内部静态库 | `lr_js_core.lib` | `liblr_js_core.a` |
| `lr_js_static` | 公共静态库 | `lr_js_static.lib` | `liblr_js_static.a` |
| `lr_js_shared` | 公共动态库 | `lr_js.dll` + `lr_js.lib` | `liblr_js.so.1.0.0` |
| `lr_js` | CLI 可执行文件 | `lr_js.exe` | `lr_js` |

- 输出目录：
  - 库文件 → `build/lib/`
  - 可执行文件 → `build/bin/`
- 平台特定链接：
  - Windows: `ws2_32` (Winsock)
  - Unix: `pthread`, `m` (math), `dl` (动态加载)
  - MSVC: 不需要 pthread（由兼容层提供）
- 安装规则：`cmake --install` 安装到标准路径

### 5. MSVC 特定配置
- `NOMINMAX` + `WIN32_LEAN_AND_MEAN` 定义
- 禁用警告：`/wd4996 /wd4244 /wd4267 /wd4100 /wd4127`
- 共享库自动定义 `LR_JS_BUILD_DLL` 和 `LR_JS_USE_DLL`

## 使用方式

### Linux/macOS
```bash

```

### Windows (MSVC)
```cmd

```
输出：
```
build\lib\Release\lr_js_static.lib
build\lib\Release\lr_js.dll

```

### 作为库嵌入
```c
#include <lr_js.h>

// 静态链接: 链接 lr_js_static.lib
// 动态链接: 链接 lr_js.lib (导入库), 运行时需要 lr_js.dll
// 定义 LR_JS_USE_DLL 使用动态链接

LR_Config cfg;
lr_config_default(&cfg);
LR_Runtime *rt = lr_runtime_new(&cfg);
lr_eval(rt, "console.log('Hello!')", 22, "inline");
lr_runtime_free(rt);
```

## 技术要点
- pthread 兼容层使用 `static __inline` 内联函数，零运行时开销
- MSVC 使用 `CONDITION_VARIABLE` (Vista+) 不需要额外库
- `LR_API` 宏设计为构建时自动切换 dllexport/dllimport
- CMake 的 `target_*` 命令确保依赖关系正确传递
- 内部库（`lr_engine`, `lr_js_core`）不暴露给用户，仅公共库安装
