### 1. TypeError 全局变量缺失问题

**问题**：`TypeError`、`RangeError`、`SyntaxError` 等错误子类构造函数未注册为全局变量，`typeof TypeError` 抛出 ReferenceError。

**根因**：`lr_builtins_core_init` 函数注册了 Object、Array、String、Number、Boolean、Function，但**没有注册 Error**。`lr_builtins_extra_init` 中的 `create_error_subclass` 尝试从全局获取 `Error` 构造函数，得到 `undefined`，导致所有错误子类注册失败。

**修复**：在 `lr_builtins_core_init` 中的 Function 注册之前，添加 Error 注册代码：

```c
/* ── Error ──────────────────────────────────────────────────────────── */
{
    JSValue error_ctor = JS_NewCFunction(ctx, lr_error_constructor, "Error", 1);
    JSValue error_proto = JS_NewObject(ctx);
    JS_SetPropertyStr(ctx, error_proto, "constructor", JS_DupValue(ctx, error_ctor));
    JS_SetPropertyStr(ctx, error_ctor, "prototype", error_proto);
    JS_SetPropertyStr(ctx, error_proto, "name", JS_NewString(ctx, "Error"));
    JS_SetPropertyStr(ctx, error_proto, "message", JS_NewString(ctx, ""));
    JS_SetPropertyStr(ctx, global, "Error", error_ctor);
}
```

**文件**：[lr_builtins_core.c](file:///workspace/LR_JS/src/lr_builtins_core.c)（第 4052-4067 行）

### 2. catch 块中 e.message 返回 undefined 的问题

**问题**：当引擎异常（如 `foo.bar` 抛出 ReferenceError）被 `try/catch` 捕获时，`e.message` 返回 `undefined`。

**根因**：`eval_try` 的 catch 处理中，`interp->error_message` 被设置但 `interp->exception_pending` 未被设置。标识符解析代码（第 365-368 行）手动设置 `interp->error_flag` 和 `interp->error_message`，但未设置 `interp->exception_pending` 和 `interp->exception_value`。导致 `exc_val = interp->exception_pending ? ... : LR_VALUE_UNDEFINED` 始终返回 `undefined`。

**修复**：重构 `eval_try` 的 catch 变量处理逻辑，处理三种情况：
1. `exception_pending` 为 true 且异常值为引擎标记（`LR_TYPE_EXCEPTION`）→ 创建 Error 对象
2. `exception_pending` 为 true 且异常值为用户抛出值 → 直接使用
3. `exception_pending` 为 false 但 `error_flag` 被设置（`error_message` 非空）→ 创建 Error 对象

同时，确保 Error 对象的原型链正确（使用 `Error.prototype` 作为原型）。

**文件**：[lr_interp.c](file:///workspace/LR_JS/src/engine/lr_interp.c)（第 2517-2566 行）
