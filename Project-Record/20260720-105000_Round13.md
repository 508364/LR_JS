### 2. 新建 `src/lr_lockfree_queue.h` — CAS 无锁队列 (MPSC)
- **MPSC (Multiple Producer, Single Consumer)**: 多生产者入队，单消费者出队
- **数据结构**: 链表 + 傀儡节点 (stub node) 避免 ABA 问题
- **`lr_lfq_init`**: 初始化队列，创建 stub 节点
- **`lr_lfq_push`**: CAS 循环入队，无锁，等待自由
- **`lr_lfq_pop`**: 单消费者出队，无需 CAS
- **`lr_lfq_peek`**: 窥视头节点
- **`lr_lfq_count`**: 近似计数
- **`lr_lfq_drain`**: 一次性取出所有节点
- **`lr_lfq_destroy`**: 销毁队列
- **内存序**: release 语义入队，acquire 语义出队

### 3. 重构 `src/lr_thread_pool.h` — 无锁队列线程池

- 保留 `signal_mutex` + `signal_cond` 用于唤醒休眠的工作线程

## 设计决策

### 为什么选择 MPSC 而不是 MPMC？
- 线程池的工作模型是：多个生产者（主线程/任意线程）向一个工作线程提交任务，每个工作线程是唯一消费者
- MPSC 的出队不需要 CAS，性能更好
- 如果要实现 MPMC，可以用多个 MPSC 队列组合

### 为什么保留 condition variable？
- 无锁队列解决的是竞争条件，不解决等待/唤醒问题
- 当队列为空时，工作线程必须休眠，否则会忙等浪费 CPU
- `signal_mutex` 仅用于 `pthread_cond_wait`，不影响队列的并发性能

### 为什么移除 epoll？
- epoll 是 Linux-only 的 API，Windows 和 macOS 不支持
- 调度器当前只需要 timer 功能，不需要真正的 I/O 多路复用
- 改为纯 timer 驱动后，所有平台使用相同的代码路径
