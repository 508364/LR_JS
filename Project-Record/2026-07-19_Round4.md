# L/R_JS Project - Round 4: 平滑分代 GC 实现

**时间**: 2026-07-19  
**主题**: 制作平滑 GC 和分代 GC，尽可能实现 GC 回收时无卡顿

---

## 概述

实现了完整的 Generational GC（分代 GC）和 Incremental GC（增量 GC）系统，以最小化 GC 暂停时间。

## 架构设计

```
┌─────────────────────────────────────────────────┐
│  Nursery (Young Gen)                            │
│  快速 bump-pointer 分配器                        │
│  Minor GC: 扫描 nursery，复制存活对象到 Old Gen  │
│  晋升: 存活 N 次 Minor GC 的对象晋升到 Old Gen  │
└─────────────────────────────────────────────────┘
                    ↓ promotion
┌─────────────────────────────────────────────────┐
│  Old Generation                                 │
│  完整 mark-sweep GC                             │
│  Major GC: 频率较低，使用增量标记               │
└─────────────────────────────────────────────────┘

Incremental GC:
  - 时间切片标记: 每步标记 N 个对象，然后让出控制权
  - 惰性清理: 在分配过程中增量清理
  - 空闲时间 GC: 事件循环空闲时执行 GC 工作
  - 暂停目标: 可配置的最大暂停时间（默认 5ms）
```

## 新增文件

### `src/lr_gc.h` - GC 模块头文件

核心数据结构：

- `LR_GCConfig` - GC 配置
  - `generational_enabled` - 启用分代 GC
  - `nursery_size` - Nursery 大小（默认 4MB）
  - `promotion_age` - 晋升前需要存活的 Minor GC 次数（默认 3）
  - `incremental_enabled` - 启用增量 GC
  - `pause_target_ns` - 目标最大暂停时间（默认 5ms）
  - `mark_step_size` - 每步标记对象数（默认 1024）
  - `sweep_step_size` - 每步清理对象数（默认 2048）
  - `gc_time_ratio` - 目标 GC 时间占比（默认 5%）
  - `major_gc_interval_ms` - Major GC 最小间隔（默认 5s）
  - `allocation_threshold` - 触发 Minor GC 的分配阈值（默认 256KB）
  - `idle_gc_enabled` - 启用空闲时间 GC
  - `stress_mode` - GC 压力测试模式

- `LR_GCStats` - GC 统计
  - GC 计数（minor/major/full）
  - 时间统计（总时间、上次暂停、最大暂停、标记时间、清理时间）
  - 增量步骤计数、空闲 GC 步骤计数
  - Nursery 统计（分配、释放、晋升、当前大小、峰值）
  - 暂停时间分布直方图（10 个桶：<1ms ~ >500ms）

- `LR_GCContext` - GC 上下文
  - Nursery 块链表（bump-pointer 分配器）
  - 增量标记状态机（idle → mark-roots → mark → remark → sweep → complete）
  - 标记工作列表
  - 清理光标
  - 分配跟踪
  - 互斥锁（线程安全）

### `src/lr_gc.c` - GC 模块实现

核心函数：

- `lr_gc_init()` / `lr_gc_destroy()` - 初始化和销毁
- `lr_gc_config_default()` - 默认配置
- `lr_gc_nursery_alloc()` - Nursery bump-pointer 分配
- `lr_gc_minor()` - Minor GC（nursery 清理）
- `lr_gc_major()` - Major GC（完整堆，支持增量）
- `lr_gc_full()` - 完整 stop-the-world GC
- `lr_gc_incremental_start()` / `lr_gc_incremental_step()` - 增量标记
- `lr_gc_idle_work()` - 空闲时间 GC（从事件循环调用）
- `lr_gc_before_alloc()` / `lr_gc_after_alloc()` - 分配钩子
- `lr_gc_print_stats()` - 打印 GC 统计
- `lr_gc_record_pause()` - 记录暂停时间到直方图

## 关键设计决策

1. **基于 QuickJS 的 GC**: QuickJS 内部使用引用计数 + 标记清除。我们的 GC 层在此基础上添加分代和增量调度。

2. **Nursery 分配器**: 使用 bump-pointer 分配器快速分配，Minot GC 时清理整个 nursery。

3. **增量标记**: 使用阶段状态机（idle → mark-roots → mark → remark → sweep → complete），每个阶段有工作预算。

4. **暂停避免策略**:
   - 将工作分散到多个事件循环周期
   - 按时间（而非工作量）预算每个步骤
   - 在空闲期间调度 GC
   - 优先 Minor GC（快速）而非 Major GC（慢速）
   - 使用 nursery 推迟 Major GC 工作

5. **GC 钩子**: 在 `lr_eval()` 和事件循环中集成 GC 检查，确保在正确的时间触发 GC。
