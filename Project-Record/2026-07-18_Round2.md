# L/R_JS 项目记录 - 第2轮对话

**时间戳**: 2026-07-18  
**对话轮次**: 第2轮  
**项目**: L/R_JS - 多线程多任务高性能轻量JS异步沙箱运行器

---

## 本轮目标

将 L/R_JS 从单线程 JS 运行器升级为：
1. **多线程多任务** - 线程池 + 沙箱隔离
2. **渲染器外挂** - IPC 桥接专业渲染器
3. **V8 性能优化** - 借鉴 V8 的关键优化技术
4. **异步沙箱** - 资源隔离 + 超时 + 内存限制

## 新增模块清单

### 1. 线程池 (lr_thread_pool.c/h)
| 特性 | 说明 |
|------|------|
| 固定大小线程池 | 可配置 1-128 个工作线程 |
| 每线程独立 JSRuntime | QuickJS 非线程安全，每线程独立隔离 |
| 优先级队列 | 4 级优先级 (LOW/NORMAL/HIGH/CRITICAL) |
| 轮询分发 | Round-robin 任务分发 |
| 任务类型 | EVAL / EVAL_FILE / CALLBACK / RENDER / TERMINATE |
| 回调通知 | 任务完成时回调 LR_TaskCallback |

### 2. 沙箱隔离 (lr_sandbox.c/h)
| 特性 | 说明 |
|------|------|
| 内存限制 | 可配置 heap 上限 |
| 执行超时 | 可配置 timeout_ms |
| 栈大小限制 | 可配置 stack_size |
| 网络/文件隔离 | allow_network / allow_filesystem 开关 |
| Worker 隔离 | allow_workers 开关 |
| 上下文隔离 | isolated_context 模式 |
| 状态追踪 | IDLE/RUNNING/TIMED_OUT/OOM/ERROR/STOPPED |
| 峰值内存追踪 | peak_memory 统计 |
| 错误计数 | error_count 追踪 |

### 3. 渲染器桥接 (lr_renderer.c/h)
| 特性 | 说明 |
|------|------|
| 外部渲染器 | Skia / Headless / WebGPU / Custom |
| 内部渲染器 | 内置 framebuffer (PPM 导出) |
| IPC 通信 | Unix Domain Socket，非阻塞 I/O |
| 共享内存 | SHM 零拷贝像素传输 |
| 命令协议 | 长度前缀 JSON 消息 |
| 帧缓冲 | 直接像素访问 API |
| 渲染命令 | PAINT / VIEWPORT / RECT / TEXT / IMAGE / CLEAR / FLUSH / SNAPSHOT / STYLE / COMPOSITE |

### 4. 任务调度器 (lr_scheduler.c/h)
| 特性 | 说明 |
|------|------|
| 优先级调度 | 基于线程池的优先级队列 |
| 延时任务 | schedule_delayed 延迟执行 |
| 重复任务 | schedule_repeat 循环执行 |
| 取消任务 | schedule_cancel |
| epoll 事件循环 | 高性能 I/O 多路复用 |
| 统计追踪 | tasks_scheduled / executed / dropped |

### 5. V8 优化模块 (lr_v8_opt.c/h)

借鉴 V8 源码的关键优化技术：

| V8 技术 | 我们的实现 | 效果 |
|---------|-----------|------|
| CodeSerializer (code-serializer.h) | BytecodeCache - FNV-1a 哈希 + LRU 淘汰 | 避免重复编译 |
| CompilationCache (compilation-cache.h) | CompileCache - 256 桶哈希表 | 缓存命中加速 |
| IncrementalMarking (incremental-marking.h) | ConcurrentGC - 后台线程 + 条件变量 | 非阻塞 GC |
| FastApiCalls (fast-api-calls.h) | FastAPICache - 直接函数指针 | 减少 C↔JS 开销 |
| Maps/HiddenClasses (map.h) | AtomCache - 预计算属性原子 | 加速属性访问 |
| LazyCompilation | Lazy Module Init - 延迟初始化 | 加速启动 |

### 6. Worker API (lr_worker.c)
| 特性 | 说明 |
|------|------|
| 多线程 Workers | 类似 Web Worker 的 API |
| 消息传递 | postMessage / onmessage |
| 错误处理 | onerror 回调 |
| 生命周期 | terminate() 终止 |
| 隔离运行时 | 每个 Worker 独立 JSRuntime |
| 全局注册表 | ID 索引避免类注册 GC 问题 |

## 关键设计决策

1. **每线程独立 JSRuntime**：QuickJS 非线程安全，线程池中每个工作线程拥有自己的 JSRuntime + JSContext
2. **Worker 全局注册表**：使用 ID 索引 + 全局链表避免 JS_NewClass/JS_SetClassProto 的 GC 问题
3. **渲染器 IPC**：Unix Domain Socket + 共享内存，支持非阻塞 I/O 和零拷贝像素传输
4. **V8 优化适配**：由于 QuickJS 是纯解释器无 JIT，重点借鉴字节码缓存、编译缓存、原子缓存等无需 JIT 的优化
