## 修复的 Bug

### ArrayBuffer-backed TypedArray 创建失败

**问题**：`new Uint8Array(ab)` 创建的 TypedArray 的 `length` 为 0，`buffer` 属性指向新创建的 buffer 而非传入的 ArrayBuffer。

**旧输出**：
```
view.length: 0
view.byteLength: 0
view.buffer === ab: false
view[0]: undefined
```

**根因**：TypedArray 构造函数中 Case 3（array-like/iterable）在 Case 4（ArrayBuffer）之前执行。当传入 ArrayBuffer 时：
1. `JS_IsObject(first)` 为 true → 进入 Case 2/3 分支
2. Case 2（TypedArray copy）因 `o->type != LR_OBJ_TYPED_ARRAY` 跳过
3. Case 3 尝试获取 ArrayBuffer 的 `length` 属性 → 不存在，`length = 0`
4. 创建零长度的 TypedArray 并返回
5. Case 4（ArrayBuffer 处理）变成**死代码**，永远不会执行

**修复**：在 [lr_builtins_extra.c](file:///workspace/LR_JS/src/lr_builtins_extra.c#L2250-L2291) 的 Case 3 中添加 `if (o->type != LR_OBJ_ARRAY_BUFFER)` 检查，跳过 ArrayBuffer 对象，让代码继续执行到 Case 4。

**修复后输出**：
```
view.length: 10
view.byteLength: 10
view.buffer === ab: true
view[0]: 42
view[1]: 255
```
