## 发现的 Bug 汇总

### Bug 1 (Critical): `lr_check_exception` 泄漏全局对象 + 逻辑错误
**文件**: `src/lr_runtime.c`
**问题**:
- `JS_GetGlobalObject(ctx)` 返回新引用但从未 `JS_FreeValue`，泄漏全局对象引用
- 调用 `JS_GetException` 两次，第二次调用丢失异常
- 逻辑混乱：先检查 `!JS_IsException(JS_GetGlobalObject(ctx))`（永远为 true）
**修复**: 简化逻辑，只调用一次 `JS_GetException`，正确判断是否有异常

### Bug 2 (Critical): `lr_fetch` 指针比较应改为 strcmp
**文件**: `src/lr_fetch.c`
**问题**: `(const char *)method != (const char *)"GET"` 比较指针地址而非字符串内容。当用户传入 `{method: "GET"}` 时，`method` 是新分配的字符串，与静态字面量 `"GET"` 地址不同，导致错误调用 `JS_FreeCString` 释放静态字符串 → 未定义行为。
**修复**: 使用 `method_allocated` 标志位记录是否动态分配了 method 字符串

### Bug 3 (Medium): `addEventListener` 内存泄漏
**文件**: `src/lr_event.c`
**问题**:
- `item` JSValue（`JS_NewObject`）push 到数组后未释放
- `EventListener *l` C 结构体 `js_mallocz` 分配后从未释放（且完全未使用）
**修复**: 添加 `JS_FreeValue(ctx, item)`，删除未使用的 `EventListener` 结构体

### Bug 4 (Medium): `removeEventListener` 实现完全错误
**文件**: `src/lr_event.c`
**问题**:
- 创建了 `filter` 函数但从未使用
- 创建空数组直接替换 `__listeners`，移除所有监听器
- `JS_FreeValue(ctx, new_listeners)` 在 `JS_SetPropertyStr` 之后调用导致 double-free
  - 原因：`JS_SetPropertyInternal` 对已存在属性使用 `set_value()` 直接存储（不调用 `JS_DupValue`），属性取得所有权后不应再释放
**修复**: 正确实现过滤逻辑：
  1. 遍历旧数组，通过函数字面量字符串比较找出匹配项
  2. 构建新数组（跳过匹配项）
  3. 释放旧数组引用
  4. 设置新数组为 `__listeners`（不释放 new_listeners，因属性已取得所有权）

### Bug 5 (Medium): URL `searchParams` 缺失原型
**文件**: `src/lr_url.c`
**问题**: URL 构造函数中 `searchParams` 用 `JS_NewObject(ctx)` 创建，无原型函数，导致 `.toString()` 返回 `[object Object]`，`.get()` 报错
**修复**: 在 URL 构造函数中为 `searchParams` 添加 `URLSearchParams` 函数列表

### Bug 6 (Low): `lr_console_group` 使用 `printf` 而非 `fprintf`
**文件**: `src/lr_console.c`
**问题**: `console.group()` 用 `printf` 输出到 stdout，而非 `fprintf(rt->stdout_fp, ...)`，与其他 console 函数不一致
**修复**: 统一改用 `fprintf(rt->stdout_fp, ...)`
